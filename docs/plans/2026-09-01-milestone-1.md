# Milestone 1 — Auth + queue + console skeleton

Goal: a real multi-tenant MCP server that **two different coding agents** can authenticate
to and coordinate work through, with a console that manages members and repos.

Billing is recorded but not enforced. Trackers are reference-only (`ticket_ref` string);
the two-way sync engine is milestone 2.

Done means: from a fresh machine, a new user signs up, enrolls TOTP, registers a repo,
adds the server to Claude Code *and* Copilot CLI, and both sessions coordinate on the same
queue with tenant isolation proven by test.

## Task 6 — `df-auth`: TOTP + sessions ✅

Email verification, TOTP enrollment (encrypted secret, provisioning URI), verification with
drift + replay refusal, recovery codes, magic-link recovery, rate limiting, constant-shape
login responses. Browser session cookies for the console.

`login` is the front door: it normalizes the address, throttles on both address and source
IP, and answers identically for an unknown address, a disabled account, a wrong code, and a
replayed one — the unknown path runs the same TOTP arithmetic and writes the same audit row.
`magic` issues single-use ten-minute links (verify / recover / invite), matching purpose in
the lookup so a verification link cannot be spent on recovery. `sessions` is the console
cookie: hashed at rest, a sliding 14-day idle window under a hard 90-day cap, dead the
moment its user is disabled.

**Mail delivery is not here and is not meant to be.** `magic::issue` returns the token; the
address it goes to, the message, and the provider are `df-web`'s (task 10) — `df-auth` does
no I/O it cannot test. Task 10's checklist below carries the two rules that side must not
get wrong.

## Task 7 — `df-auth`: OAuth 2.1 AS ✅

Both `.well-known` documents, RFC 7591 dynamic client registration, `/oauth/authorize`
(+ consent), `/oauth/token` with PKCE S256, rotating refresh tokens, RFC 8707 resource
indicators, opaque hashed tokens, scope model, revocation. Plus personal access tokens for
the fallback client path.

## Task 8 — `df-mcp`: server + tools ⬜

`rmcp` Streamable HTTP mount, resource-server middleware (audience enforcement, principal
injection, `401` + `WWW-Authenticate` discovery hint), then the tool surface from the spec.
Tool descriptions written for an LLM caller with no docs.

## Task 9 — `df-billing`: recording ⬜

`usage_events` write + `org_period_usage` increment inside the tool's transaction, the
free/billable classification table, `whoami` and `usage` tools. Enforcement is behind a
flag, default off.

## Task 10 — `df-web`: console API ⬜

Session auth, org/member/team/repo CRUD, invites, PAT mint/revoke, usage read. OpenAPI
generated from the handlers. Owns magic-link delivery, and two rules come with it:

- **Consume a link on `POST`, never on the `GET` that renders the page.** Corporate mail
  scanners follow every URL in every message, and a single-use `GET` is spent before the
  human clicks it.
- **Session cookies**: `HttpOnly`, `Secure`, `Path=/`, `SameSite=Lax` — `Lax` because
  `/oauth/authorize` is reached by a top-level navigation and `Strict` would drop the cookie
  there.

## Task 11 — `web/`: Svelte 5 console ⬜

SvelteKit 2 + Svelte 5 runes + Tailwind v4. Sign-up/TOTP enrollment, members, teams, repos,
queue read-only view, usage meter, "connect your agent" page rendering the exact command
per client.

## Task 12 — Client conformance ⬜

Verify against Claude Code and Copilot CLI end to end. Record `docs/clients/matrix.md`.
Any client that fails the OAuth path gets the PAT path documented instead.

## Task 13 — Deploy ⬜

Dockerfile, startup migrations under advisory lock, health/readiness endpoints, structured
logging, Fly.io config, first live deploy.

## Sequencing

Tasks 2→5 are the critical path and strictly ordered. 6→7 can start once 2 lands. 8 needs
5 and 7. 9 needs 8. 10→11 need 7. 12 needs 8 deployed. Nothing after task 5 blocks task 6,
so auth and the queue proceed in parallel.

## Rule for every task

A task is done when its tests pass, `cargo clippy --all-targets -- -D warnings` is clean,
and `cargo fmt --all --check` is clean. Tenant-scoped functions are not done without a
cross-org negative test.
