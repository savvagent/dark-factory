# Milestone 1 — Auth + queue + console skeleton

Goal: a real multi-tenant MCP server that **two different coding agents** can authenticate
to and coordinate work through, with a console that manages members and repos.

Billing is recorded but not enforced. Trackers are reference-only (`ticket_ref` string);
the two-way sync engine is milestone 2.

Done means: from a fresh machine, a new user signs up, enrolls TOTP, registers a repo,
adds the server to Claude Code *and* Copilot CLI, and both sessions coordinate on the same
queue with tenant isolation proven by test.

## Task 6 — `df-auth`: TOTP + sessions ✅

Email verification, TOTP enrollment (encrypted secret, provisioning URI), verification with
drift + replay refusal, recovery codes, magic-link recovery, rate limiting, constant-shape
login responses. Browser session cookies for the console.

`login` is the front door: it normalizes the address, throttles on both address and source
IP, and answers identically for an unknown address, a disabled account, a wrong code, and a
replayed one — the unknown path runs the same TOTP arithmetic and writes the same audit row.
`magic` issues single-use ten-minute links (verify / recover / invite), matching purpose in
the lookup so a verification link cannot be spent on recovery. `sessions` is the console
cookie: hashed at rest, a sliding 14-day idle window under a hard 90-day cap, dead the
moment its user is disabled.

**Mail delivery is not here and is not meant to be.** `magic::issue` returns the token; the
address it goes to, the message, and the provider are `df-web`'s (task 10) — `df-auth` does
no I/O it cannot test. Task 10's checklist below carries the two rules that side must not
get wrong.

## Task 7 — `df-auth`: OAuth 2.1 AS ✅

## Task 8 — `df-mcp`: server + tools ✅

`rmcp` Streamable HTTP mount, resource-server middleware (audience enforcement, principal
injection, `401` + `WWW-Authenticate` discovery hint), then the tool surface from the spec.
Tool descriptions written for an LLM caller with no docs.

**27 tools**: repos (4), jobs (13), coordination (9), `whoami`. `usage` and `whoami`'s
quota field belong to task 9; `link_ticket` and `sync_ticket` are milestone 2, since
milestone 1 keeps trackers to the `ticket_ref` string.

Decisions worth carrying forward:

- **The principal is per request, not per session.** An MCP session spans many HTTP
  requests and the token is re-introspected on each one, so revoking a token in the console
  stops it on the agent's next call rather than at some unbounded later point.
- **The transport is stateless** (`stateful_mode: false`, `json_response: true`). Nothing
  is ever pushed to a client — `watch` is a long poll the agent initiates — so a
  server-held session would buy nothing and cost sticky routing across replicas.
- **`rmcp` defaults `allowed_hosts` to loopback**, which silently rejects every request to
  a hosted server. `Config` requires it.
- **Every result is a one-field object** (`{"job": …}`, `{"jobs": […]}`). MCP requires an
  `outputSchema` rooted at `object`, so a bare array is not a legal result — and an
  envelope can gain a field later without breaking callers.
- **`df-core` now derives `JsonSchema`** alongside the `Serialize` it already had, so tool
  results describe themselves without a parallel set of view types to drift.

`Watcher` gained `shutdown()`: `PgListener` detaches a connection from the pool that
nothing was reclaiming. That is a graceful-shutdown leak in production and a hang in tests,
where the throwaway database cannot be dropped while a session is still attached.

## Task 9 — `df-billing`: recording ✅

`usage_events` write + `org_period_usage` increment inside the tool's transaction, the
free/billable classification table, and the `usage` tool. Enforcement is behind a flag,
default off. `whoami` gained its `usage` field.

The split with `df-core`: every statement against a tenant table lives in `df_core::usage`
and goes through a pinned `Tx`; `df-billing` owns the policy — which tools cost anything,
what a bucket is worth, when a call is refused. That keeps the interesting decisions
unit-testable with no database at all.

Decisions worth carrying forward:

- **The meter runs before the work, not after**, immediately after the tool opens its
  transaction. That looks backwards for "a failed call is not billed" and is exactly what
  makes it true: the usage row is in the tool's own transaction, so a failure rolls the
  meter back with it. Charging afterwards would need a second transaction that can fail,
  be retried, or be forgotten. It also puts the quota check where a refusal is cheapest.
- **`watch` is the exception** and meters in a transaction of its own, committed before
  the wait. Holding a transaction open for thirty seconds per idle agent would exhaust
  the pool long before the queue was busy. It is free, so there is no billing consequence.
- **Unclassified tools are free, loudly.** The asymmetry is the point: defaulting to
  billable means a tool nobody priced silently charges customers, and the first person to
  notice is one reading a bill. `classify::exhaustive_over` turns it into a test failure —
  `every_tool_has_a_price` compares the router against the price list.
- **Lease renewal and release are free**, alongside the reads. Charging per renewal bills
  an agent for holding still; charging for release creates an incentive not to release,
  which costs everyone else the branch until it expires. Coordination hygiene must not
  have a price on it.
- **Enforcement refuses billable work and never reads.** An org that runs out mid-task can
  still see its queue, understand what happened, and go and upgrade.

**Not done, and deliberately deferred**: the design's "at 80% of the bucket the server
attaches a warning to tool results and emails org admins". The threshold and the `warning`
flag exist and are reported by `usage` and `whoami`; threading a notice through all 29
tool result envelopes, and the admin email, are milestone 2. The plan's own scope for this
task did not include them.

## Task 10 — `df-web`: console API ✅

Session auth, org/member/team/repo CRUD, invites, PAT mint/revoke, usage read, the audit
trail, an OpenAPI document, and magic-link delivery. Both rules the plan attached to this
task hold, and both are asserted rather than trusted: `every_single_use_redemption_is_a_post`
and `the_cookie_carries_every_attribute_that_protects_it`.

**It also carries the authorization server's HTTP surface** — `/oauth/authorize` (consent
page and decision), `/oauth/token`, `/oauth/register`, `/oauth/revoke`, and both
`.well-known` documents. Task 7 built the AS as pure logic with no transport, and nothing
else in the plan owns mounting it; it landed here because `/oauth/authorize` is a browser
surface that needs precisely the session cookie this task builds. That is the same fact the
plan's own `SameSite=Lax` note was pointing at.

**`df-core` needed two modules first**, which tasks 3–5 had not covered: `teams` (CRUD,
rosters, resolution) and `invites` (mint, list, revoke, peek, accept). Both are tenant
tables with cross-org negative tests in `isolation.rs`, per the rule in `CLAUDE.md`.

Decisions worth carrying forward:

- **A verification link opens a session only while the account has no confirmed TOTP.**
  Something has to break the bootstrap circle — logging in needs a second factor, enrolling
  one needs a session. Before enrollment, control of the mailbox *is* the strongest factor
  the account has and the same one the user would present anyway; the moment an
  authenticator exists the link stops being enough, so a verification mail opened later on
  a phone marks the address verified and nothing more. `df_auth::login::verify_email`
  deliberately opens no session and leaves this decision to the caller.

- **An org you are not in is `404`, never `403`.** A `403` on a real slug and a `404` on a
  fake one turns any signed-in account into a directory of who uses the product. Both
  collapse in `session::OrgCtx`, which is also where membership and role are decided —
  once, in an extractor, rather than in each handler where forgetting is invisible.

- **The router and the OpenAPI document are built from one list.** `catalog.rs` declares
  each endpoint with its handler *and* its prose; `router()` folds it into axum and
  `openapi::document` renders it. Drift is not detected, it is impossible. The honest cost:
  component schemas are hand-written, so a new field on a response struct does not appear
  in the document by itself.

- **Removing a member revokes their tokens for that org and nothing else.** Their sessions
  and their tokens in other orgs survive — a session is not org-scoped, and signing someone
  out of an unrelated customer's console is not that button's business. `df-auth` gained
  `tokens::revoke_all_in_org` for it.

- **`RepoPatch::team_id` is `Option<Option<TeamId>>`.** Found by a test: with a plain
  `Option`, "absent" and "clear it" collapse, so a team-scoped repo could never be
  unscoped — and since `delete_team` refuses while repos still reference it, the team
  became undeletable. Absent / set / clear are three states and the type now says so.

- **OAuth protocol errors keep their own words.** Identity failures collapse to
  `AuthError::public`, which is the enumeration defense; `invalid_scope` and friends
  describe the caller's own request, so RFC 6749 §5.2 returns them verbatim and so do we.
  Also found by a test — the first draft flattened `unknown scope "jobs:destroy"; supported
  scopes are …` down to the bare word `invalid_scope`.

- **The consent screen leads with the redirect host.** Registration is open, so anyone can
  register a client called "Claude Code"; the name is rendered as the untrusted string it
  is (escaped, and asserted escaped), and the host the code will actually be delivered to
  gets the visual weight. Every issuable scope has a sentence a person can weigh, enforced
  by `every_issuable_scope_is_explained_in_words`.

- **Mail delivery is a trait, and the trait is the deliverable.** A provider needs an
  account, a verified sending domain, SPF/DKIM, and a bounce policy — deployment decisions,
  not crate decisions. `LogMailer` is loud on purpose: a quiet no-op mailer is
  indistinguishable from a working one until somebody asks why nobody has joined.

- **No transaction is held open across a mail send.** An invitation is written, committed,
  and then mailed; a failed send withdraws it. The tidier-looking order — commit only after
  a successful send — would pin a pooled connection to someone else's SMTP latency, which
  is the same trade `watch` refuses in task 9. The cost is a brief window where a live
  invitation exists that nobody has received, which is harmless: it is single-use, it
  expires, and a retry supersedes it.

- **`throttle_by_source` is charged before the address is looked up.** Charging it only on
  the path that actually sends would make the throttle itself an enumeration oracle — an
  attacker would watch their own budget move and learn which addresses exist.

**Deferred, deliberately**: enterprise OIDC federation and domain claiming (the console
routes for `idp_connections` / `claimed_domains`), and org deletion. Neither is in this
task's scope and both need decisions — DNS verification flow, what deleting an org does to
its job history — that milestone 1 does not have to make.

## Sequencing

Tasks 2→5 are the critical path and strictly ordered. 6→7 can start once 2 lands. 8 needs
5 and 7. 9 needs 8. 10→11 need 7. 12 needs 8 deployed. Nothing after task 5 blocks task 6,
so auth and the queue proceed in parallel.

With 10 done, 11 and 13 are both unblocked and independent. 12 needs 13, since a client
conformance run needs a URL an agent can actually reach.

## Rule for every task

A task is done when its tests pass, `cargo clippy --all-targets -- -D warnings` is clean,
and `cargo fmt --all --check` is clean. Tenant-scoped functions are not done without a
cross-org negative test.
